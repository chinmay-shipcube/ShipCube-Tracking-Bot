SHIPCUBE TRACKING BOT - DATABASE SETUP (Firebase, one time)
===========================================================
You need: a Google account with Owner/Editor on the company's Firebase project, Node.js 20 installed.
The project must be on the Blaze (pay-as-you-go) plan - the company already has it.

1. FIREBASE CONSOLE (console.firebase.google.com) > your project
   a. Build > Firestore Database > Create database > Production mode > location (e.g. us-central1 or nam5).
   b. Build > Authentication > Get started > Sign-in method > Email/Password > Enable.
   c. Authentication > Users > Add user - one login per teammate, email ends with @shipcube.com.
   d. Project settings (gear) > General > Your apps > Web app (</>) > register it > copy "apiKey".
      That key goes into the bot's Settings as "Firebase Web API key". (It is not a secret.)

2. ON YOUR PC (once)
   npm install -g firebase-tools
   firebase login
   cd "<this folder>\firebase"
   firebase use <your-project-id>
   cd functions && npm install && cd ..
   firebase deploy --only functions,firestore:rules

   The output shows the function links, for example:
   https://us-central1-<project-id>.cloudfunctions.net/sync
   The bot needs the part BEFORE /sync:
   https://us-central1-<project-id>.cloudfunctions.net

3. IN THE BOT (each PC)
   Settings > Database: paste the link from step 2 and the apiKey, your @shipcube.com email and password,
   press Sign in. The password is used once and not stored - only a refresh token is kept.
   Then turn "Save to database too" on and run the bot as usual. Sheet and database both get the results.

TEST
   Settings > Database > Test connection (calls "ping"). Expect: signed in as you@shipcube.com.

NOTES
   * Functions only accept signed-in @shipcube.com accounts. Firestore rules block all direct access.
   * Every run writes: shipments (one doc per tracking number, with all sheet columns in "sheet") and
     shipments/<number>/history (one entry each time the status changes).
   * Delivered is never overwritten by a later status.
   * If the database can't be reached, the sheet is still updated; the bot shows "Database write paused"
     and retries on the next run.
